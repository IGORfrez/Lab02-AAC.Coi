## В моём эксперименте Release оказался быстрее Debug примерно в
3,5 раза.
Что я обнаружил при сравнении IL:
--В Debug присутствуют инструкции nop, которых нет в Release.  
--​В Release уменьшилось количество промежуточных операций с локальными переменными (отсутствуют лишние слоты и команды stloc/ldloc).  
--​Количество IL-инструкций в методе Add() уменьшилось (в Release код метода стал короче и состоит всего из нескольких базовых инструкций).
## Ответы на контрольные вопросы
1.IL — это промежуточный байт-код, получаемый после компиляции C#-программы. Он нужен для того, чтобы отделить исходный код от конкретной архитектуры процессора, позволяя .NET запускать одну и ту же сборку на разных платформах, где JIT-компилятор на лету преобразует IL в машинные инструкции.
2.Потому что .NET-сборка хранит внутри себя не чистый машинный код, а IL-инструкции вместе с подробными метаданными о типах, классах и методах. 
3.В конфигурации Debug присутствуют отладочные инструкции и больше операций с локальными переменными на стеке, тогда как в Release компилятор применяет оптимизации, убирая лишний код и сокращая количество инструкций.
4.Потому что режим Release настроен на максимальную производительность: компилятор и JIT-среда выполняют глубокие оптимизации кода, удаляя избыточные проверки, отладочную информацию и промежуточные операции.
5.Строковые литералы сохраняются внутри скомпилированной сборки в открытом виде (в виде обычного текста без шифрования), поэтому любой человек может легко обнаружить их с помощью декомпилятора или HEX-редактора.
